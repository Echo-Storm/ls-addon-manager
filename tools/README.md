# Tools

Scripts to build, test, look at and package LS Addon Manager. They find the repository from their own location, so run them from anywhere.
Where a script needs your Lossless Scaling folder it takes `-LsDir` (or reads the `LS_DIR` environment variable); the default is the usual Steam path.

**Rules the tools follow**

- Nothing here needs a visible window. Testing uses an offline host and an offscreen renderer, so it never takes over your screen.
- `deploy.ps1` never replaces files under a running game: it refuses while the game or Lossless Scaling runs, and backs up what it overwrites.
- The GPU test (`run_hosttest_matrix.py`) loads the GPU for about 20 seconds per scenario, three at a time. Do not run it while a game runs.

| Tool | What it does |
|---|---|
| `make_pm_shortcut.ps1` | Puts a **LS Project Manager** icon on the desktop (`-StartMenu` too): a double-click starts `dev.py serve` with no console window and opens the board in the browser; a second double-click only opens it again. Port 8761, or the next free one if something of yours is on it (`.dev/serve.json` remembers which); the page has a Stop button. The icon is drawn by `make_pm_icon.py`. |
| `dev.py` | One front door for the everyday work, plain Python (stdlib), run from the repository or a worktree, not tied to any chat: `status` (what is built, deployed, released), `serve` (**LS Project Manager**: the board as a local page at 127.0.0.1:8761; move cards, add items, run the cheap checks), `board [--html]` (handoff/BOARD.md from handoff/board.json and the open issues; a commit line `Board: ID status` moves a card), `test`, `gen` (frame generation scores against saved baselines), `presenter`, `build`, `deploy`, `logs`, `rec`, `map`/`find`/`show` (where things are, ranked searches that fit a token budget), `selftest`. Results go to the ignored `.dev/`. `python tools/dev.py --help`. |
| `build_all.ps1` | Configures (first time) and builds the manager, the Neural Rendering addon, the UI preview and the offline test host, Release x64. `-Only host,nr`. |
| `run_addon_tests.ps1` | Offline tests, no game needed, in suites (core, features, sample, update, gui, installer, setupexe, nr). By default it builds and runs only the suites that the files changed since the last commit can affect, and prints only failures and the time each suite took. `-Only core,gui` picks suites, `-All` runs every one (before a release), `-List` shows what starts each. |
| `run_hosttest_matrix.py` | Runs the Neural Rendering test host through its scenarios (Neural Rendering, the DLSS, FSR and XeSS Upscalers, recording, the pair) and checks the presented frame against a synthetic pattern. Three at a time (`--jobs`), printing only failures (`--verbose` for every check). `--changed`: only the scenarios for the files changed since the last commit (what `run_addon_tests.ps1` uses); `--quick`: the everyday set; no option: all but the retired ones (`RETIRED` in the script says why each is; `--retired` or `--only` runs them). About 5 minutes for all. Needs `nvngx_dlssnr.dll` (`--snippet` or `LS_DIR`). |
| `nr_fgeval.exe` (built with the addons) | Frame generation scored offline on a recording (`.lsrec`, made with frame generation off): every other frame is rebuilt by AMD's FSR 3.1 (`gen=fsr`) or Intel's XeSS (`gen=xess`, needs `fetch_xess_sdk.ps1`) frame generation, fed this project's motion estimate, and compared with the real one, beside a repeat and a 50/50 blend; the worst frames are saved as pictures. `nr_fgeval <recording> <folder> [gen=] [first=] [count=] [worst=] [depthdir=] [motion=none]`. Findings: `docs/frame-generation-research.md`. Our own synthesis (`src/engine/own_synth.cpp`): `own=1 direct=1` makes the frames with it (`ownscale=1|2|4` analysis cell size, `ownmult=N` several frames per pair, `owt=` the time scored, `ownhdr=1` the recording's own half-float frames), `engine=1 engineown=1 [enginemult=N]` through `FgEngine` as live; `flowdump=N` writes raw triples (the frames and our motion both ways) for `interp_flow_lab.py`; `NR_SYNTH_STOP=N` in the environment runs only the first N passes, to time them. |
| `nr_fgpresent.exe` (built with the addons) | The frame generation presenter (`src/addon/framegen11.cpp`) on a real swap chain with the addon's Present hook and a synthetic moving scene; every frame shown is read back and the square's position checked: how many frames per real frame (`mult=2..9`), their order, where they are (`own=0` FSR, `hdr=1`, `fps=`, `speed=`), and the same with the multiplier changed while it runs (`switch=1`), a resized swap chain (`resize=1`) and a source that repeats each frame (`fps=60 dup=2`). How the swap chain is presented, for the display timing study: `sync=0|1|2`, `tearing=1`, `latency=N` (a waitable chain, Lossless Scaling's Max frame latency), `buffers=N`, `size=2|4` (1080p or 4K); it then prints how long the Present calls took. Part of `run_addon_tests.ps1`'s nr suite. |
| `interp_lab.py`, `interp_flow_lab.py` | CPU labs (numpy) for frame interpolation ideas on small versions of real frames: `interp_lab.py <folder of nr_lsrec export>` (block matching, the first findings), `interp_flow_lab.py <folder of nr_fgeval flowdump triples>` (synthesis on this project's own motion: splatting, both directions, hole fill; `--auto-t`, `--invert`, `--cubic`). Results: `docs/own-generator-plan.md`. |
| `nr_sreval.exe` (built with the addons) | `realonly=1` runs the upscaler on every other frame only and gives the rest the engine's cheap run (what frame generation could do; docs/frame-generation-research.md). An upscaler scored offline on a recording (`.lsrec`): each frame is shrunk (`shrink=150`) and upscaled back by the addon's own engine (`backend=dlss\|fsr\|xess`), against the true frame (dB, steadiness) and, with no reference, the flicker and detail against the game's own frames. Options mirror the panel: `sharpen=`, `restmix=` (Sharpness at rest), `steady=`, `movecut=` (Sharpen less in fast motion), `lean=easu`, `flowreuse=`, `edges=`, `preset=`. `dup=N` gives every frame of the recording N times in a row (a 30 fps game in a 60 Hz capture feed) and prints the output's change on the repeats against the new frames and the detail on each (the upscalers do not pulse on a doubled source, 2026-10-08). `hdr=1` runs an HDR recording as fp16 light (scored tone-mapped, and with checks: nothing non-finite, mean light and peak kept; `hdrcheck=1` makes them the exit code); `debug=1\|2` turns on the D3D12 debug layer (2: GPU-based validation; its layout message on the shared output texture comes from the tool, not from a pass); `bench=N` runs the last frame N times back to back for GPU times that are not inflated by an idle card. |
| `nr_nreval.exe` (built with the addons) | Neural Rendering's model run offline on a recording (needs your own `nvngx_dlssnr.dll`, `lsdir=`): the model's change where the game's frame did not move (levels of 255; the number to bring down), along the motion, the lighting shift (`lightlog=1`), by `smooth=`, `stable=`, `scale=`; `dup=N`: each frame given N times, with the model's change and brightness shift on the repeats against the new frames. |
| `nr_composebench.exe` (built with the addons) | The GPU time of Neural Rendering's compose pass (`Compose11`) run back to back on a made-up 4K frame, for SDR and HDR (`encoding=0\|1\|2`, `sharpen=`, `size=`); `once=1 dump=file` writes one run's pixels, to compare two versions of the shader (a run feeds the next, so only one run compares). The times in a live log or a host-test scenario are taken with an idling GPU and vary by a factor of five. |
| `nr_lsrec.exe` (built with the addons) | Looks into recordings: `info`, `export` (frames as BMP, HDR tone-mapped), `make` (a made-up moving picture for tests; `hdr=1`: fp16 light with bright glints). `nr_lsrec flicker <file>`: how much the picture changes from one frame to the next (levels of 255, every 4th pixel), by the kind of pair (real to made, made to real, for a recording of what is shown), the biggest steps with their time between frames, and whether the change repeats at some period (a pulse every Nth frame). |
| `sr_default_grid.py` | Runs `nr_sreval` over a grid of Sharpening x Sharpness at rest x Steady sharpening on some recordings and prints one table (how the defaults were chosen: `python tools/sr_default_grid.py 150 dlss <clips>`). |
| `ci.ps1` | The tests that need neither a GPU, a game nor NVIDIA's SDK, from a clean checkout: what the GitHub Actions build runs on every push (version check, the manager's tests, the addon's offline tests in `addons\DLSS5NR01\tests`, the sample addon). |
| `pack_recordings.ps1` | Compresses saved recordings (`.lsrec`) after the fact, lossless and checked before anything is removed: Zstandard (`-Method zstd`, a third of the size for HDR) or FFV1 video (`-Method video`); `-RemoveOriginals` only after the check. |
| `fetch_*.ps1` | Fetch the SDKs and runtimes the addons build against into `addons\DLSS5NR01\external` (NGX, FidelityFX, FSR 4, XeSS, the Agility SDK, the depth model); none of them is redistributed in the repository. |
| `gpu_logger.ps1` | GPU load, clocks, power and throttle reasons once a second to a CSV (nvidia-smi), stopping itself after `-Minutes`. Read-only. |
| `setup_obs_for_tests.ps1`, `setup_shots.ps1`, `make_menu_clip.py`, `make_readme_shots.py`, `make_echo_icon.py` | OBS profile for recording what the addons show; the README's Setup pictures; a synthetic ghost-test recording; the README's panel pictures; the icon. |
| `video_pacing.py` | The pacing of a recording of the screen (what a capture card or recorder saw of Lossless Scaling's output): new pictures a second, how long each picture stayed (frames of the recording), the longest freezes with their times, the moving seconds on their own, the evenness; `--cuda` decodes 4K HEVC on the card, `--csv` writes every frame. It warns when the scene is too low in contrast to tell repeats from new pictures. Used on a player's footage of the Skyborne area (kept outside the repository). |
| `analyze_addon_log.py` | Reads an addon's log (`DLSS5NR01.log`, `DLSS4DLAA.log`, ...) and prints what a report needs: the game's frame time window by window (bumpy windows: p95 over 1.6x p50), the model's cost and how long it waited for the card, the upscaler's GPU cost and motion share, Lossless Scaling's compose pass, auto quality's changes, and what switched things off. `python tools/analyze_addon_log.py <log> [more] [--out report.md]`. Standard library only. |
| `analyze_frame_trace.py` | Reads the frame trace the addons write (`logs\frame-trace-<addon>.csv`, at shutdown and when a recording is saved): the pacing of the presented and the real frames, the longest gaps with what happened around them, the model's and the upscaler's numbers. `python tools/analyze_frame_trace.py <csv> [--out report.md]`. Standard library only. |
| `nr_xadapter.exe` (built with the addons) | The plumbing for running the model on a second graphics card: a cross-adapter heap, placed buffers and a shared fence between two D3D12 devices, a 66 MB copy checked pixel for pixel and timed (the second adapter is WARP when there is one card). `debug=1` prints the debug layer's reasons when the heap is refused. Findings and the design: docs/dual-gpu.md. |
| `bump_version.py` | Every place that holds the release number, in one go: `python tools/bump_version.py 1.0.1` says what it would change, `--apply` writes it (the addon API's own number is left alone). |
| `dlssg_probe\` (own CMake project; needs NVIDIA's Streamline SDK in `addons\DLSS5NR01\external\streamline`, not in the repository) | A lab: drives NVIDIA's frame generation (DLSS-G) from a window that is not a game, with synthetic or recorded pictures and the motion of your choice, and scores the generated frames against the true ones (`check_grab.py`, `check_clip.py`, `score_dump.py`). Results: `docs/mfg-super-motion-study.md`. Not part of any build or release. |
| `flowlab\` (own CMake project; needs the four NVIDIA Optical Flow headers in `addons\DLSS5NR01\external
vof`) | A lab: motion measured by this project's flow estimator and by NVIDIA's optical flow hardware on the same recorded frames, scored by interpolating the frame between (`score_flow.py`). Results: `docs/optical-flow-study.md`. Not part of any build or release. |
| `sr_option_check.sh` | Compares the upscalers' test options (Crisp edges, Motion by shape) on some recordings against the defaults. |
| `fetch_depth_model.ps1` | Fetches Depth Anything V2 Small (ONNX, Apache 2.0, a pinned revision and SHA-256) into `addons\DLSS5NR01\external\depth`: depth from a single picture, for the frame generation experiments. |
| `depth_maps.py` | Depth maps for exported frames (`nr_lsrec export`), with that model on the GPU (DirectML), for `nr_fgeval`'s `depthdir=`. Needs its own Python once: `py -m venv tools\.venv`, then `tools\.venv\Scripts\pip install onnxruntime-directml numpy pillow`. |
| `ui_preview.ps1` | Renders every tab, the addon cards and the addon panels offscreen to PNG. Set `EAM_PREVIEW_CLEAN=1` for the tidy scene used in the README. |
| `make_readme_shots.py` | Crops those renders into `docs/images`. |
| `compare_ui_renders.py` | Compares two folders of offscreen renders picture by picture (used to prove a rewrite of window code changed nothing you can see). |
| `measure_original_share.py` | How much of `manager/src` and `manager/sdk` is still the code this project started from, against a checkout of the original (see NOTICE.md). |
| `package.ps1` | Builds the release zip in `dist\` (`-Version`, `-SkipBuild`). Never packages NVIDIA's SDK or the DLSSNR snippet. |
| `fetch_xess_sdk.ps1` | Fetches Intel's XeSS SDK (release 3.0.2: headers, `libxess.dll`, and for `nr_fgeval` `libxess_fg.dll` and `libxell.dll`, licence) into `addons\DLSS5NR01\external\xess`, checked by SHA-256 and Intel's signature. Without it the XeSS Upscaler is not built. |
| `deploy.ps1` | Copies a build into a Lossless Scaling folder, with backups. `-What host\|nr\|dlaa\|fsr\|xess\|all`. |
| `analyze_ls_logs.py` | Summarises `DLSS5NR01.log`: frame-time distribution, model cost, presets applied. |
| `gpu_logger.ps1` | `nvidia-smi` once a second to a CSV; stops itself after 45 minutes. |
| `make_echo_icon.py` | Draws the Echo icon (`manager/manager-icon.ico` and `.png`), each size on its own. |
| `bmp2png.py` | BMP to PNG for a folder (needs Pillow). |
